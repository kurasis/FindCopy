# FindCopy 1.0.1

This maintenance release includes the reviewed fixes from the code and end-user
security audits. It preserves the application's scanning and recovery interfaces.

- Validate directory-record offsets before native decoding to reject malformed
  responses without unsigned wraparound or out-of-buffer reads.
- Require explicit confirmation before opening any found file through its Windows
  association, including document types with custom executable handlers.
- Preserve unrelated files in dense acceptance datasets and reject linked dataset
  markers before generation can create or overwrite an external target.
- Close handles/connections on failed keeper and cache initialization; join started
  I/O workers on scheduler failure and use monotonic timing for autotuning.
- Save settings atomically and restore UI controls after deletion errors or
  cancellation. Keep existing settings when replacement fails.

The release contains self-contained Windows x64 and ARM64 executables, built with
.NET SDK 8.0.425 and runtime 8.0.31. Windows validation runs on Windows 11 ARM64,
including native ARM64, x64 emulation, WPF interaction, SMB, and a standard user
running the published executable. SHA-256 checksums accompany both executables.

Authenticode signing is not configured. The residual risks and investigation
limits remain documented in [the security audit](../security-audit-2026-10-07.md);
this release is not a certification of complete application safety.
